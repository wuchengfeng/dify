# Starship 第一批页面低保真线框（草案 v0.1）

更新时间：2026-04-01

状态：可进入结构讨论

适用对象：老板、前端负责人、CTO

文档目的：先把第一批核心页面的结构定下来，不谈颜色，不谈视觉风格，只谈页面骨架和使用顺序。

## 1. 这份文档怎么用

你看这份文档时，只需要关注 3 件事：

1. 这页的信息摆放顺不顺。
2. 老师和孩子会不会迷路。
3. 关键按钮是不是放在最顺手的位置。

这份文档先不讨论：

1. 颜色
2. 字体
3. 插画
4. 视觉风格

## 2. 第一批先画哪 6 页

第一批先做下面 6 页，因为这 6 页决定课堂主链路能不能跑通：

1. 教练首页
2. 任务管理页
3. 实时课堂看板
4. 学生首页
5. 任务工作区
6. 版本审核页

## 3. 教练首页

这页的目标：

教练一登录，就知道今天先干什么。

### 3.1 页面骨架

```text
+--------------------------------------------------------------+
| 顶部栏：页面标题 | 当前小组 | 快速入口                         |
+--------------------------------------------------------------+
| 今日任务                                                [进入看板] |
| - 当前任务 1                                                  |
| - 当前任务 2                                                  |
+--------------------------------------------------------------+
| 需要关注                                                      |
| - 刚提交的学生                                                |
| - 被退回后又更新的学生                                        |
| - 刚测试过的学生                                              |
+--------------------------------------------------------------+
| 待处理                                                        |
| - 待审核版本                                                  |
| - 待发布主版本                                                |
+--------------------------------------------------------------+
```

### 3.2 这页最重要的按钮

1. 进入实时课堂看板
2. 新建任务
3. 去审核
4. 去主版本管理

### 3.3 这页设计原则

1. 不做复杂图表。
2. 不让教练找入口。
3. 打开就能看见今天最急的事。

## 4. 任务管理页

这页的目标：

让教练清楚地发任务，并且知道新任务会不会覆盖旧任务。

### 4.1 页面骨架

```text
+--------------------------------------------------------------+
| 顶部栏：任务管理 | [新建任务] | 筛选                           |
+--------------------------------------------------------------+
| 左侧：任务列表                                                |
| - 任务A  进行中                                               |
| - 任务B  已结束                                               |
| - 任务C  未开始                                               |
|                                                              |
| 右侧：任务详情 / 新建任务                                     |
| 任务名：_____________________                                 |
| 发给小组：___________________                                 |
| 任务说明：___________________                                 |
|                                                              |
| 提示：若学生已有旧任务，本次发送将自动结束旧任务              |
|                                                              |
|                              [取消]   [创建并发送]            |
+--------------------------------------------------------------+
```

### 4.2 这页必须说清楚的事

1. 发给谁。
2. 当前任务状态是什么。
3. 新任务发出后，旧任务会怎么处理。
4. 旧任务不是消失了，而是被系统自动结束。

### 4.3 我建议的页面感觉

这页要像“发课堂作业”，不要像复杂后台。

## 5. 实时课堂看板

这页的目标：

让教练一个屏幕看到整节课。

### 5.1 页面骨架

```text
+--------------------------------------------------------------------------------+
| 顶部信息条：任务名 | 小组名 | 已提交人数 | 当前课堂状态                          |
+--------------------------------------------------------------------------------+
|                                                                                |
|        学生1窗口          教练主窗口                    学生2窗口               |
|   名字 / 状态 / 内容      当前版本 / 测试区              名字 / 状态 / 内容     |
|                                                                                |
|        学生3窗口                                         学生4窗口               |
|   名字 / 状态 / 内容                                   名字 / 状态 / 内容       |
|                                                                                |
|        学生5窗口                                         学生6窗口               |
|   名字 / 状态 / 内容                                   名字 / 状态 / 内容       |
|                                                                                |
|                                                   右侧快捷操作区               |
|                                                   - 测试这个学生               |
|                                                   - 查看这个学生版本           |
|                                                   - 写反馈                     |
+--------------------------------------------------------------------------------+
```

### 5.2 页面核心规则

1. 学生窗口保持平铺。
2. 不把学生切到中间。
3. 点学生后，右侧直接打开测试和查看入口。
4. 教练测试完，仍然留在这张课堂页面里。

### 5.3 每个学生窗口至少要有

1. 学生名
2. 当前状态
3. 最近动作时间
4. 当前正在写的内容
5. 快捷测试入口

### 5.4 我建议的重点

这页不是“管理后台”，而是“课堂现场”。  
所以最重要的是看见谁在动、谁刚提交、谁现在写到哪。

## 6. 学生首页

这页的目标：

孩子一登录，马上知道下一步干嘛。

### 6.1 页面骨架

```text
+--------------------------------------------------------------+
| 顶部欢迎区：你好，XX同学                                      |
+--------------------------------------------------------------+
| 当前任务                                                      |
| 任务名：______________                                        |
| 当前状态：进行中 / 已提交 / 需修改                            |
|                                               [继续当前任务]  |
+--------------------------------------------------------------+
| 老师反馈                                                      |
| - 最近一次老师说了什么                                        |
+--------------------------------------------------------------+
| 最近作品                                                      |
| - 作品A                                                       |
| - 作品B                                                       |
+--------------------------------------------------------------+
```

### 6.2 这页最重要的按钮

1. 继续当前任务
2. 看老师反馈
3. 进入自己的作品

### 6.3 这页设计原则

1. 不给孩子太多选择。
2. 不让孩子先读大段说明。
3. 直接给一个很明显的“继续当前任务”按钮。

## 7. 任务工作区

这页的目标：

孩子点进来就开始做，不被拦住。

### 7.1 页面骨架

```text
+--------------------------------------------------------------------------------+
| 顶部状态条：任务名 | 当前状态 | 保存状态 | [测试] [提交]                         |
+--------------------------------------------------------------------------------+
|                                                                                |
| 左侧任务说明          中间主创作区                           右侧简要状态       |
| - 任务要求            - 孩子正在写内容                        - 最近一次测试      |
| - 完成标准            - 沿用现有创作能力                      - 是否已保存        |
| - 可随时收起          - 不重做编辑器                          - 是否可提交        |
|                                                                                |
+--------------------------------------------------------------------------------+
| 底部结果区：最近一次测试结果 / 系统自动保存状态                                 |
+--------------------------------------------------------------------------------+
```

### 7.2 孩子在这页必须看懂的 4 件事

1. 我现在在做哪个任务。
2. 我现在能不能测试。
3. 我现在能不能提交。
4. 我为什么还不能分享。

### 7.3 这页的重要原则

1. 一进来直接能写。
2. 任务说明不要挡住主创作区。
3. 测试和提交按钮要明显。
4. 自动保存要让孩子感到安心。

## 8. 版本审核页

这页的目标：

让教练处理学生提交内容，不混乱。

### 8.1 页面骨架

```text
+--------------------------------------------------------------------------------+
| 左侧：提交列表         | 中间：学生版本内容                | 右侧：审核操作       |
| - 学生A 10:20提交      | - 当前内容                         | - 老师反馈输入框     |
| - 学生B 10:35提交      | - 测试结果                         | - [退回修改]         |
| - 学生C 11:00提交      | - 关键提示词                       | - [通过]             |
|                        | - 当前状态                         |                       |
+--------------------------------------------------------------------------------+
```

### 8.2 这页必须支持的动作

1. 看学生当前版本
2. 看学生提示词
3. 写反馈
4. 退回
5. 通过

### 8.3 这页必须提醒教练的规则

1. 可以参考学生内容。
2. 可以吸收学生提示词。
3. 不能直接把学生版本设成 `main`。

## 9. 第一批页面的跳转关系

```text
教练登录
  -> 教练首页
    -> 任务管理页
    -> 实时课堂看板
      -> 版本审核页

学生登录
  -> 学生首页
    -> 任务工作区
      -> 版本审核结果会回到学生首页和版本记录
```
