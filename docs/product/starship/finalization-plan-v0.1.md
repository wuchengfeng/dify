# Starship 第一阶段定稿时间表（v0.1）

更新时间：2026-04-02

这份文档只回答 3 个问题：

1. 现在做到哪了
2. 还差什么
3. 什么时候能算定稿

## 1. 现在做到哪了

如果只看前端方案准备，我判断现在已经完成了大约 `80%`。

已经完成的部分：

1. 第一阶段范围已经定了。
2. 关键业务规则已经定了。
3. 教练端、学生端、对外页面已经拆完。
4. 三批页面线框已经落盘。
5. 页面按钮、状态词、提示语已经整理。
6. 页面空状态、异常提示、跳转关系已经整理。
7. 前端和 CTO 的第一版对接清单已经整理。

## 2. 现在还差什么

要到“可以真正开工，而且不容易返工”的程度，还差 4 步：

1. 把第一批 6 页再细化成更接近真实页面的结构稿。
2. 把第二批、第三批页面里容易冲突的地方收一遍。
3. 和 CTO 过一轮对接清单，确认后端能不能承住。
4. 把最后的版本合成一份“正式定稿版”。

## 3. 我给你的时间判断

如果按现在这个推进速度，不被打断：

1. 到 `2026年4月3日`，我可以把前端方案文档基本收口。
2. 到 `2026年4月4日`，我可以把第一阶段页面方案整理到“适合和 CTO 对齐”的版本。
3. 如果 `2026年4月4日` 或 `2026年4月5日` 能和 CTO 过一轮，那么第一阶段方案可以在 `2026年4月5日` 前后进入正式定稿。

## 4. 什么叫“正式定稿”

我这里的“正式定稿”不是开始写代码，而是指下面这些都稳定了：

1. 页面不再大改。
2. 规则不再反复改。
3. 前端知道每页做什么。
4. CTO 知道后端要提供什么。
5. 老板看起来也觉得主流程是顺的。

## 5. 我接下来会怎么推进

我会按这个顺序继续做：

1. 先把第一批 6 页继续细化。
2. 再把所有页面再做一次总检查。
3. 再把可拿给 CTO 的版本单独整理出来。
4. 最后合成一份正式定稿版。

我会继续往下推进，尽量把需要你拍板的点压到最少。
