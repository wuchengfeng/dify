## 1. 先说结论

我建议第一阶段页面按下面三块来做：

1. 教练端 6 页
2. 学生端 5 页
3. 对外 3 页

这样拆的好处是：

1. 先把课堂主链路做通。
2. 前端知道先画什么，后画什么。
3. CTO 后端也知道先支持哪些能力。

这一版我再补一条最关键的页面原则：

教练不是先“建组”，而是先看到业务系统里已经分给自己的组，然后进入某一个组，在组里做任务、课堂、审核和主版本。

## 1.1 下一次直接写代码的顺序

下一次不再讨论时，我会直接按下面顺序开工：

1. 先做教练首页的“我的组”入口
2. 再做组内的任务管理页
3. 再做组内的实时课堂看板
4. 再做学生首页和任务工作区
5. 再做版本审核页
6. 最后补主版本管理、发布和对外页

这样做的原因很简单：

先把“进入组 -> 建任务 -> 上课 -> 审核”这条课堂主链路跑通，后面的发布和传播再接上。

## 3. 第一阶段最重要的 4 条用户路线

### 3.1 教练发任务

1. 教练登录
2. 进入教练首页
3. 先进入某一个组
4. 打开这个组的任务管理页
5. 创建任务并发给这个组
6. 如果学生已有旧任务，系统自动结束旧任务
7. 教练进入这个组的实时课堂看板

### 3.2 学生做任务

1. 学生登录
2. 进入学生首页
3. 看见当前任务
4. 点开后直接进入任务工作区
5. 写、测、存
6. 提交给教练

### 3.3 教练定主版本

1. 教练在看板里看学生实时进展
2. 教练直接测试学生作品
3. 教练在审核页给反馈
4. 教练吸收学生提示词到自己的版本
5. 教练和孩子们达成共识
6. 教练在主版本管理页发布自己的 `main`

### 3.4 学生公开自己的版本

1. 教练主版本发布
2. 学生基于主版本继续改
3. 学生进入我的发布页
4. 设置封面、简介、作者名
5. 生成公开链接
6. 自动进入公共展示区
7. 外部用户先看介绍页，再进入体验页

## 4. 教练端页面线框说明

这部分不是视觉稿，而是页面骨架。后面画页面时，就按这些区块来。

### 4.1 教练首页

页面目标：

让教练一登录就知道今天要处理什么。

页面建议分成 4 块：

1. 顶部区
   放页面标题、当前小组、快速入口。
2. 我的组区
   放业务系统里已经分给这个教练的组，支持进入某一个组。
3. 今日任务区
   放今天进行中的任务、刚创建的任务、可直接进入看板的按钮。
4. 需要关注区
   放“刚提交的学生”“被退回后又更新的学生”“最新测试的学生”。
5. 待处理区
   放待审核版本、待发布主版本。

页面上必须让教练一眼看到的 5 件事：

1. 当前能带哪些组
2. 现在正在看哪个组
3. 当前正在跑哪个任务
4. 哪些学生有新动作
5. 哪些版本待审核
6. 有没有可发布的主版本

### 4.2 任务管理页

页面目标：

让教练发任务、看任务、结束任务。

这里先写死一条：

任务一定是在“进入某一个组之后”创建，不是脱离组单独创建。

页面建议分成 3 块：

1. 顶部操作区
   放当前组、“新建任务”按钮和任务筛选。
2. 任务列表区
   每一条任务显示：
   任务名、小组、当前状态、开始时间、结束时间、当前学生数。
3. 任务详情抽屉
   点开一条任务后，看到任务要求、目标学生、小组信息、任务状态。

这个页面必须特别处理 2 件事：

1. 如果学生已有进行中的旧任务，教练发新任务时，页面要明确提示“旧任务会自动结束”。
2. 旧任务结束后，系统要留下清楚记录，别让老师和学生误会是数据丢了。

### 4.3 实时课堂看板

页面目标：

让教练像看课堂一样，一屏看到自己和最多 6 个孩子的实时状态。

这里也先写死一条：

课堂看板只属于当前组，不跨组混看。

页面建议分成 4 块：

1. 顶部信息条
   放组名、任务名、当前课堂状态、已提交人数。
2. 中间教练主窗口
   放教练自己的版本、当前测试区、当前课堂焦点。
3. 周围 6 个学生窗口
   每个学生窗口至少要有：
   学生名、当前状态、最近动作时间、当前正在写的内容。
4. 右侧操作区
   放“测试这个学生智能体”“查看这个学生版本”“写反馈”的快捷入口。

这个页面最重要的交互规则：

1. 学生窗口保持平铺。
2. 不需要把某个学生切到中间主窗口。
3. 教练点某个学生后，直接进入“测试这个学生”的动作。
4. 教练测试完后，能快速回到课堂总览。

我建议这里用“右侧滑出测试面板”的方式，不打断整张课堂看板。

### 4.4 学生进度页

页面目标：

让教练按任务看清楚每个学生做到哪一步。

这里的查看范围也要固定：

先看当前组，再看当前组里的任务，不跨组混在一起。

页面建议分成 3 块：

1. 顶部任务切换区
   放当前组、当前任务和历史任务切换。
2. 中间学生列表区
   每个学生显示：
   学生名、当前状态、最近测试时间、最近提交时间、最近更新时间。
3. 右侧反馈区
   点开某个学生后，看到老师最后一次反馈和当前版本摘要。

这个页面更像“班级总表”，和实时看板的区别是：

1. 实时看板是看课堂现场。
2. 学生进度页是看全班整体进度。

### 4.5 版本审核页

页面目标：

让教练处理学生提交的版本。

这里默认只看当前组、当前任务相关的提交，不看全租户混在一起。

页面建议分成 3 块：

1. 左侧学生提交列表
   放谁提交了、什么时候提交的、当前待处理状态。
2. 中间内容查看区
   放学生当前版本内容、测试结果、关键提示词。
3. 右侧审核操作区
   放老师反馈输入框、通过按钮、退回按钮。

这个页面要特别强调：

1. 教练可以看学生提示词。
2. 教练可以吸收内容，但不能直接把学生版本设成 `main`。
3. 审核页的结果要能回流到学生版本记录里。

### 4.6 主版本管理页

页面目标：

让教练维护唯一的正式版本。

这里的主版本也是“当前组、当前任务”的主版本。

页面建议分成 4 块：

1. 当前主版本区
   显示现在正在生效的教练版本。
2. 教练候选版本区
   只展示教练自己的版本。
3. 课堂共识说明区
   记录这次主版本为什么定成这一版。
4. 发布操作区
   放发布按钮、发布时间、发布说明。

这个页面必须写死一条规则：

主版本只能来自教练自己的版本。

## 5. 学生端页面线框说明

### 5.1 学生首页

页面目标：

让学生一登录就知道“我现在该做什么”。

页面建议分成 4 块：

1. 顶部欢迎区
   放昵称、当前任务状态。
2. 当前任务区
   放“继续当前任务”的大按钮，也放任务列表入口。
3. 老师反馈区
   放最近一次反馈。
4. 最近作品区
   放自己最近改过的作品。

这个页面最重要的是：

不要让孩子思考太多，直接告诉他下一步是什么。

### 5.2 任务工作区

页面目标：

让学生直接开始创作，不被多余说明挡住。

页面建议分成 4 块：

1. 顶部状态条
   放任务名、当前状态、保存、测试、提交。
2. 中间主创作区
   沿用现有创作能力，不重做新编辑器。
3. 侧边任务说明区
   不单独拦路弹出，而是收在侧边，需要时展开看。
4. 底部结果区
   放最近一次测试结果、系统自动保存状态。

这个页面必须满足 4 件事：

1. 一进来就能写。
2. 只要测试过，系统就记住进度。
3. 孩子知道自己当前是否能提交。
4. 孩子知道当前为什么还不能分享。

### 5.3 我的作品页

页面目标：

让学生分得清“我在做的”“我已经发的”“我是从主版本拉出来的”。

页面建议分成 3 块：

1. 进行中的作品
2. 已发布的作品
3. 来自主版本的作品

每张作品卡至少显示：

1. 作品名
2. 当前状态
3. 最近更新时间
4. 是否可发布

### 5.4 版本记录页

页面目标：

让学生看懂自己一路是怎么被老师反馈和推进的。

页面建议就是一条清楚的时间线：

1. 哪次测试
2. 哪次提交
3. 老师什么时候反馈
4. 什么时候被退回
5. 什么时候通过

这里不追求复杂对比，先追求“孩子能看懂”。

### 5.5 我的发布页

页面目标：

让学生在允许分享后，把自己的公开版本发出去。

页面建议分成 4 块：

1. 封面设置区
2. 一句话介绍区
3. 作者名设置区
4. 发布结果区

这里有 3 条页面规则：

1. 如果当前还不能分享，要明确告诉孩子原因。
2. 作者名由学生自己定义。
3. 系统默认提示优先用昵称或作品名，不鼓励直接写真实联系方式。

## 6. 对外页面线框说明

### 6.1 公共展示区

页面目标：

让外部用户浏览已经公开的作品。

页面建议分成 3 块：

1. 顶部标题区
2. 作品卡片区
3. 筛选区

第一阶段先做简单浏览，不做复杂活动页。

### 6.2 作品介绍页

页面目标：

让外部用户先理解这个作品，再决定要不要点进去体验。

页面建议分成 5 块：

1. 封面图
2. 作品名
3. 一句话介绍
4. 作者名
5. 开始体验按钮

这页要优先按手机端 H5 来设计。

### 6.3 作品体验页

页面目标：

让外部用户真正体验作品。

第一阶段建议直接承接现有体验能力，不另外新做一套。

## 7. 页面优先级

我建议前端按 3 批来画。

### 第一批：先把主链路画出来

1. 教练首页
2. 任务管理页
3. 实时课堂看板
4. 学生首页
5. 任务工作区
6. 版本审核页

原因：

这 6 页决定“能不能跑通课堂”。

### 第二批：把发布和版本体系补完整

1. 主版本管理页
2. 学生进度页
3. 版本记录页
4. 我的发布页

原因：

这 4 页决定“能不能把课堂成果稳定发布出去”。

### 第三批：把传播体验补完整

1. 公共展示区
2. 作品介绍页
3. 作品体验页
4. 我的作品页

原因：

这 4 页更偏传播和整理，不是课堂第一秒就必须要有。

## 8. 页面跳转关系

### 8.1 教练端

1. 登录后进入教练首页
2. 教练首页可以去任务管理页
3. 教练首页也可以直接进实时课堂看板
4. 实时课堂看板可以打开学生进度页
5. 实时课堂看板也可以直接进入版本审核页
6. 版本审核页处理完后，可以回看板或去主版本管理页
7. 主版本管理页发布成功后，可查看对外效果

### 8.2 学生端

1. 登录后进入学生首页
2. 学生首页直接进入任务工作区
3. 任务工作区可以去版本记录页
4. 主版本发布后，学生可以从任务工作区或我的作品页进入我的发布页
5. 我的发布页发布成功后，可查看自己的介绍页和体验页

### 8.3 对外页面

1. 公共展示区进入作品介绍页
2. 作品介绍页进入作品体验页

## 9. 前端和 CTO 后端的对接清单

这部分我用最直白的话写，方便你和 CTO 讨论。

### 9.1 登录和分流

CTO 需要给前端：

1. 当前登录的人到底是教练还是学生
2. 登录后默认要进哪个首页

### 9.2 任务

CTO 需要给前端：

1. 教练发任务的能力
2. 当前任务发给了谁
3. 学生当前是不是已经有进行中的任务
4. 发新任务时，旧任务如何被自动结束
5. 旧任务结束后，前端能拿到清楚的结束原因

### 9.3 实时课堂看板

CTO 需要给前端：

1. 最多 6 个学生当前的实时内容
2. 每个学生当前状态
3. 最近动作时间
4. 是否已测试、是否已提交
5. 教练直接测试学生作品的能力

### 9.4 审核和反馈

CTO 需要给前端：

1. 学生提交列表
2. 每次提交的内容
3. 教练反馈保存
4. 通过和退回

### 9.5 主版本

CTO 需要给前端：

1. 教练自己的版本列表
2. 哪个版本当前是主版本
3. 发布主版本的能力
4. 保证主版本只能来自教练版本

### 9.6 学生继续创作

CTO 需要给前端：

1. 学生从主版本拉一份到自己名下
2. 学生继续修改和发布
3. 学生版本和教练主版本的关联关系

### 9.7 分享和公开

CTO 需要给前端：

1. 公开链接
2. 封面图
3. 一句话介绍
4. 学生自定义作者名
5. 公开后自动进入公共展示区

### 9.8 默认保护

我建议和 CTO 先约定两条默认保护：

1. 作者名输入时，前端和后端都做一层检查。
2. 明显像手机号、微信号的内容，直接提示不要这样写。

## 10. 我建议下一步怎么做

接下来我建议这样推进：

1. 我先出第一批页面的低保真线框。
2. 你看完后，只拍板页面结构，不纠结颜色和视觉细节。
3. 页面结构定了，我再和 CTO 对齐上面的对接清单。
4. 前后端都准备好之后，再开始正式写代码。

这一步做完，前端开工会稳很多，也更不容易返工。
