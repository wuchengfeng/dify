# Starship 第一阶段后端对接清单（v0.1）

更新时间：2026-04-03

适用对象：CTO、前端负责人、产品负责人

状态：

1. 前端主流程已经用 mock 跑通
2. 现在要把 mock 换成真实后端能力
3. 这份只写“后端必须给什么”，不写复杂技术方案

---

## 1. 先说后端必须理解的业务骨架

后端请先按下面这条业务线理解 Starship：

1. 组来自业务系统
2. 一个教练会带多个组
3. 教练先进入某一个组
4. 在这个组里发布任务
5. 孩子只看自己当前所在组的当前任务
6. 孩子在课堂里先做“当前项目”
7. 教练课堂里能看到孩子正在写什么
8. 教练发布 `main`
9. 系统自动给每个孩子生成“我的发布版”
10. 孩子从“我的发布版”进入“发布与分享”
11. 外部用户匿名访问作品

后端只要把这条线守住，前端就不会返工。

---

## 2. 组和孩子不能串班

这是第一优先级的后端规则。

后端需要保证：

1. 当前登录的人能拿到真实身份：
   - 教练
   - 学生
2. 教练能拿到自己当前负责的组列表
3. 学生能拿到自己当前所在的组
4. 孩子同一时间不能在多个组的多个进行中任务里同时活跃
5. 如果业务系统里孩子换组，Starship 里也要同步生效

前端需要的结果：

1. 教练进来只看到自己带的组
2. 学生进来只看到自己当前应该看到的班和任务
3. 不出现孩子串班、串任务

建议后端至少给出：

1. 当前用户身份
2. 当前用户所在组 / 所带组
3. 当前进行中的任务
4. 当前任务是否已结束

---

## 3. 教练发布后，孩子立刻能看到

这件事后端要保证“快”，不一定要复杂。

后端需要支持：

1. 教练在某个组里创建任务
2. 教练发布任务给这个组
3. 这个组里的孩子立刻能在学生首页看到
4. 如果孩子之前还有旧任务，旧任务要自动结束
5. 旧任务结束后要留记录，但不能再继续做

前端需要的结果：

1. 教练点发布后，孩子刷新后马上就能看到
2. 学生首页“当前项目”永远只有当前该做的那个
3. 旧项目会留在历史，不会消失

建议后端给出：

1. 当前任务
2. 历史任务
3. 任务发布时间
4. 任务结束时间
5. 任务结束原因

---

## 4. 教练端实时看到孩子写的提示词

这是课堂产品的核心能力，不是可有可无。

后端需要支持：

1. 孩子当前正在写的提示词内容
2. 孩子最近一次更新时间
3. 孩子当前状态
4. 教练课堂页拉某个组时，拿到最多 6 个孩子的当前内容
5. 允许几秒延时，不要求绝对实时

可以接受的实现方式：

1. WebSocket / 推送
2. 或者 2-5 秒一次轮询

前端需要的结果：

1. 教练一眼就能看到孩子此刻在写什么
2. 不是只看历史版本
3. 不是只看最后一次提交
4. 是看“当前编辑中的内容”

建议后端给出：

1. 学生 id
2. 学生名字
3. 当前提示词文本
4. 最近更新时间
5. 当前是否在线
6. 当前是否正在测试

---

## 5. 孩子测试后自动记版本

这条现在前端已经按这个心智做了，后端必须接上。

后端需要支持：

1. 孩子测试一次时，把当前内容一起保存
2. 如果这次测试前后内容有变化，就自动落一个新版本
3. 不需要单独让孩子点“保存”
4. 孩子版本历史能回看
5. 教练也能看孩子版本历史，但课堂页不用展开给老师看

这里要再补一条执行规则：

“内容有变化”不能靠感觉判断，后端需要有明确比对方式。  
建议至少按下面这些字段做一次内容指纹或摘要比较：

1. 提示词
2. 作品介绍
3. 开场白
4. 知识资料列表

前端需要的结果：

1. 孩子只管改和测
2. 系统自动存
3. 后面版本回放有据可查

建议后端给出：

1. 当前草稿内容
2. 最近一次自动版本
3. 历史版本列表
4. 每个版本的时间
5. 每个版本的主要内容摘要

---

## 6. 教练发布 `main` 后，自动给孩子生成“我的发布版”

这条一定要后端兜住，不要让孩子自己手动 fork。

后端需要支持：

1. 教练在某个组、某个任务下发布自己的 `main`
2. 一旦正式发布，这个 `main` 就视为定稿，不再改
3. 系统自动给该组每个孩子生成一份“我的发布版”
4. 每个孩子每个任务只保留一份“我的发布版”
5. 孩子的“我的发布版”要记住来源：
   - 来源于哪个组
   - 来源于哪个任务
   - 来源于哪个 `main`

前端需要的结果：

1. 孩子首页自动出现“我的发布版”
2. 孩子不用理解 `fork`
3. 孩子只看到“继续修改我的发布版”

建议后端给出：

1. 发布版 id
2. 对应孩子 id
3. 来源 main id
4. 来源组 id
5. 来源任务 id
6. 当前发布版是否已公开

---

## 7. 发布与分享页：后端要给哪些数据

前端现在已经把“发布与分享”从工作区里单独拆出来了。

后端需要支持的字段：

1. 对外显示的名字
2. 作品介绍
3. 开场白
4. 当前公开状态
5. 当前公开链接
6. 当前二维码
7. 海报列表

这里有 3 条业务规则必须写死：

1. 同一个作品，二维码长期不变
2. 开场白是体验页第一句，不可缺失
3. 海报不是临时现做，而是系统提前准备
4. 未正式发布前的预览，不走公开匿名链路，必须走登录态预览或签名预览
5. 对外显示的名字，要拦手机号、微信号这类联系方式

建议后端给出：

1. `public_name`
2. `share_intro`
3. `opening_line`
4. `site_code` 或固定公开地址
5. `qr_code_url`
6. `poster_templates`
7. `is_public`
8. `published_at`

---

## 8. 海报：要能真正拿出去分享

这是你们今年续费相关的核心功能，后端不要把它当附件功能。

后端需要支持：

1. 教练发布 `main` 后，自动给每个孩子预生成海报
2. 海报至少 3 个风格
3. 孩子更新公开内容后，海报同步更新
4. 二维码永远指向这个作品的固定地址
5. 海报支持前端直接下载

前端需要的结果：

1. 孩子一到“发布与分享”页，就能看到高质量海报
2. 不是点分享后才慢慢生成
3. 孩子不用理解复杂配置

建议后端给出：

1. 海报 id
2. 海报标题
3. 海报图片地址
4. 海报使用的二维码
5. 最近更新时间

如果后端第一阶段来不及真生成图片，也至少要先给前端一套稳定的海报模板数据，后面再切到真实图片生成。

---

## 9. 外部体验数据不能写回孩子自己的创作记录

这是一个很容易被忽略，但上线后会出问题的点。

后端需要保证：

1. 外部用户在公开体验页里的聊天，不写进孩子自己的测试记录
2. 外部用户的聊天，不生成孩子的自动版本
3. 外部用户的聊天，不更新孩子作品的课堂编辑时间
4. 如果要留体验日志，要单独记在公开访问日志或会话日志里

前端需要的结果：

1. 孩子自己的测试历史，只保留自己和老师在创作阶段的测试
2. 外部体验人数再多，也不会污染孩子的版本轨迹
3. 课堂编辑数据和公开体验数据彻底分开

---

## 10. 匿名访问：不登录也能直接打开孩子作品

这是传播前提。

后端需要支持：

1. 外部用户不登录也能打开作品
2. 先到介绍页
3. 再到体验页
4. 介绍页和体验页都走公开链路，不依赖控制台登录态
5. 但未发布作品的预览，必须和公开访问分开

前端需要的结果：

1. 扫码就进
2. 不跳登录
3. 不让外部用户看到后台内容

建议后端给出：

1. 公开作品查询接口
2. 公开体验接口
3. 公开作品状态
4. 公开作品被关闭时的返回状态
5. 预览接口或签名预览地址

---

## 11. 给孩子正反馈：类似 GitHub star

这是你特别关心的，我建议第一阶段就落地。

后端需要支持：

1. 外部用户不登录也可以给正反馈
2. 一个设备 / 一个浏览器不要无限重复点
3. 有总数显示
4. 孩子能看到自己的作品被喜欢了多少次

这块不一定叫 `star`，可以叫：

1. 点亮一下
2. 给个喜欢
3. 送一颗星

第一阶段最稳的后端做法：

1. 不登录也能点
2. 用设备标识 / 浏览器标识做简单去重
3. 做基础频率限制
4. 返回当前总数

建议后端给出：

1. 当前喜欢数
2. 当前设备是否点过
3. 点一次后的最新总数
4. 作品的正反馈列表摘要（可选）

---

## 12. 教练端课堂页还需要的真实数据

除了实时提示词，还要补这几类信息：

1. 孩子当前版本 id
2. 孩子最近测试时间
3. 孩子最近一次自动版本时间
4. 教练是否可以直接测试这个孩子当前版本
5. 教练自己的主版本内容
6. 教练主版本的知识资料

前端现在已经把教练课堂页收成投屏模式。  
后端把这些真实数据接上之后，教练端才算真正可上课。

---

## 13. 对接顺序建议

为了不返工，我建议 CTO 按这个顺序接：

1. 登录身份
2. 组和组成员
3. 当前任务 / 历史任务
4. 孩子不能串班的约束
5. 教练发布后孩子可见
6. 课堂实时提示词
7. 自动版本
8. 教练 `main`
9. 自动生成孩子的“我的发布版”
10. 发布与分享
11. 匿名访问
12. 点亮 / star

---

## 14. 一句话总结

后端现在最核心的工作，不是再加一堆管理页，而是把下面 4 件事做稳：

1. 孩子不能串班
2. 教练能几秒内看到孩子写的提示词
3. 教练 `main` 发布后，孩子自动拿到自己的发布版和海报
4. 外部用户匿名打开作品，并能给孩子正反馈
